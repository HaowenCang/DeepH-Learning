## 3. BLOCKING finding

### M5-C7-B01：T-C01 失败例多执行一次未记录更新，违反冻结的固定 12 步协议

**位置：** `03_textbook/chapters/07_scf_algorithms/examples.md:86-91`；对照 `08_audits/M5_stageC_work_package.md` 的 T-C01 失败规范及 `04_derivations/stageC/07_scf_fixed_point.md:210-217`。

当前代码为：

```python
x = np.zeros(3)
residuals = []
for _ in range(13):
    residuals.append(np.linalg.norm(J @ x + b - x))
    x = x + 2.0 * (J @ x + b - x)
assert residuals[-1] > 10.0 * residuals[0]
```

循环的第 `m` 次迭代先记录 `x_m` 的残差，再执行 `x_m -> x_(m+1)`。`range(13)` 因此记录 `x_0` 至 `x_12` 的 13 个残差，却执行从 `x_0 -> x_1` 到 `x_12 -> x_13` 的 13 次更新；最后一次更新产生的 `x_13` 没有被记录或验证。断言碰巧仍比较正确的第 12 步残差与初残差，四个代码块也因此全部退出 0，但“断言通过”不能证明“固定执行 12 步”的协议符合性。

该问题判为 `BLOCKING`，原因是 T-C01 的故障注入已由阶段工作包冻结为强制可执行规范，更新次数属于测试输入与成本/轨迹语义的一部分，而不是不影响结论的格式细节。当前代码在映射调用、更新次数和最终内部状态上均与冻结规范不一致；未来若验证器记录映射次数、返回终态或在更新中引入状态，额外更新会改变制品。

**最小修复要求：** 只执行 12 次更新，并显式保存初始残差及每次更新后的残差，使轨迹恰为 `x_0,...,x_12`；不得在记录 `x_12` 后再更新。修复后应重新原样执行该 Python 块，确认更新次数为 12、残差条目为 13、末残差对应 `x_12`、末/初残差比仍大于 10，并由独立定点复核关闭本 ID。
