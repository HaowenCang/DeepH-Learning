### 3.1 机读预算账本合同

预算合同的项目侧规范文件为 [`budget_contract.json`](../06_reproduction/manifests/budget_contract.json)，实际账本位于 Linux 工作根 `manifests/budget_ledger.jsonl`。统一口径如下：

- 7 天墙钟从 M9-01 定点复核通过后执行的第一个变更性 M9 命令开始，以 UTC 起点和 `604800` 秒固定截止；只读审计和工作包修订不计入。每个后续命令启动前检查当前 UTC，命令本身以剩余秒数为 `timeout` 上限。
- GPU 时间按单张冻结 GPU 上所有 M9 CUDA 进程占用区间的并集累计，不按进程重复相加；成功、失败、异常退出、OOM、烟雾、训练、验证、复跑、推理和诊断全部计入。每个区间记录桶、UTC/单调时钟起止、PID、退出码、命令 SHA-256、配置 SHA-256 和累计秒数。
- GPU 区间只能归入一个互斥桶：`compatibility=7200` 秒、`training=57600` 秒、`physical_validation=21600` 秒；三桶总和为 `86400` 秒。环境/GPU 烟雾和 CUDA 导入归兼容桶；训练、训练中验证和训练复跑归训练桶；冻结模型后的推理、矩阵/对称性/能带/诊断归物理桶。
- 大型软件、环境、下载、解压数据、图、检查点、日志和运行时结果只能位于 `/home/evan-williams/deeph-m9`。项目侧只允许保存 `budget_contract.json` 明示白名单中的小型清单、配置、脚本、测试、控制文档和 M9 审计/报告；白名单对象合计不得超过 `1073741824` 字节，不得借白名单保存数据集、环境、检查点或其他大型运行时对象。
- 存储同时记录 Linux 工作根和项目侧白名单对象各自的逻辑表观/实际分配字节、两者合计值，以及宿主 `E:\Laptop\WSL\ext4.vhdx` 相对墙钟起点的增长；合计表观字节、合计分配字节和 VHDX 增长分别不得超过 `107374182400` 字节。下载、解压、图生成和训练前必须记录当前值、下一原子操作的保守预测增量和预测后值。
- 达到任一墙钟、GPU 总/子桶、项目侧 1 GiB 子上限或总存储上限，或者预测下一不可分割操作会越界时，必须拒绝启动该操作，写入 `HARD_STOP` 账本事件并暂停。不得通过清理已登记证据、把大型对象移入项目侧白名单、移动到其他合同外路径或漏记失败运行规避预算。

## 4. 顺序门控

### M9-01：工作包独立审计

审计冻结对象、路径、授权边界、预算、失败条件和阶段 F 最低验收是否完整。只有问题为 0 才开始系统包、语言环境和 DeepH 安装。

### M9-02：WSL 与隔离环境

以宿主 WSL root 入口安装必要系统编译/压缩/线性代数工具，无需传递用户口令。在普通 Linux 用户目录安装固定 Python 环境和 Julia。必须输出：

- WSL 注册位置、发行版、内核、用户、根文件系统余量；
- 宿主和 WSL 内的 GPU 身份；
- 安装器 URL、SHA-256 和版本；
- 精确传递依赖锁与 `pip check`/等价一致性检查；
- 环境创建和重建命令。

若 PyTorch 1.9.1/CUDA 11.1 无法在计算能力 8.9 上正确运行，必须保留完整错误，判为兼容性门控失败并暂停。不得自行升级 PyTorch、CUDA、PyG 或 DeepH-pack。

### M9-03：DeepH-pack 固定源码与兼容性烟雾测试

从官方仓库检出固定提交，保存源树提交、clean/dirty 状态和关键安装元数据哈希。烟雾门控至少包括：

1. `import torch`、`torch_geometric`、`e3nn`、`deeph`；
2. CPU 和 CUDA 张量运算；
3. GPU 前向、反向和有限梯度；
4. PyG 最小消息传递或等价聚合；
5. e3nn 最小表示/张量积前向与反向；
6. DeepH-pack CLI 帮助和最小配置解析；
7. 两个新进程中的版本、设备和数值摘要一致性。

兼容性烟雾测试累计不超过 2 GPU 小时。

### M9-04：官方数据下载与数据契约

下载只允许指向冻结的 Zenodo graphene 文件。完成字节数、登记 MD5、本地 SHA-256、ZIP 完整性和安全解压检查；拒绝绝对路径、父目录逃逸、重复规范路径和异常链接。解压后必须先生成只读清单，再判断：

- 结构 ID、原子种类、坐标、晶胞和周期维度；
- Hamiltonian、overlap、轨道/basis、单位、局部坐标与截断信息；
- 官方训练配置、划分、标签和参考物理量；
- 各数组 shape、dtype、有限性、键空间和稀疏模式；
- 是否足以执行矩阵、k 空间、广义本征和能带验收。
- 逐项判定刚体旋转、空间反演和无自旋时间反演的适用性，并为适用项定位结构/k 点配对、轨道基变换、相位与 parity 数据；缺少合法对象时必须说明是否触发数据契约失败。

若缺少关键对象，冻结为数据契约失败并暂停；不得补造正式数据或改变成功声明。

### M9-05：划分、配置与训练

优先采用固定版本官方配置或数据中的显式划分。若不存在，则按结构 ID 排序并形成结构分组、不泄漏的 80%/10%/10% ID 清单，先保存 SHA-256 再训练。所有 Python、NumPy、PyTorch、CUDA 和数据加载随机源使用规范种子 `20260811`。

批量大小从 1 开始按显存实测提高；最终值、峰值显存、OOM 失败样例和选择依据必须登记。规范训练/验证累计不超过 16 GPU 小时。检查点、配置、stdout/stderr、环境锁、数据/划分 SHA 和墙钟/GPU 时间必须互相链接。

### M9-06：矩阵、对称性和物理验证

最低检查不能缩减：

- 轨道块尺寸、单位、排序、稀疏键和 provenance；
- 预测矩阵有限性、Hermiticity、逆边和平移关系；
- overlap 的 Hermiticity、适用的正定性和条件数；
- 刚体旋转：对存在合法基变换对象的结构执行 AO 块协变回拉，冻结主动/被动方向、轨道表示、edge/k 键、残差归一化和定向错误失败样例；
- 空间反演：对存在合法反演配对或可构造同一冻结模型输入的对象，按轨道 parity 与 k 点映射验证 H/S 关系，并执行漏 parity 或错配对失败样例；
- 无自旋时间反演：非磁、无 SOC graphene 至少验证成对 k 点的 `H(k)=H(-k)^*`、`S(k)=S(-k)^*` 及对应广义谱对称性，冻结 Fourier 相位、k 点规范键、简并匹配和漏共轭失败样例；
- 全矩阵及轨道分辨误差；
- 实空间到 k 空间重建和广义本征残差；
- 全能带、费米能窗、带隙、带宽、DOS、简并和可获得的本征态指标；
- 结构分组的分布内/外结果；若官方数据不能支持合法 OOD 声明，必须明确记为不可评估，不得伪造拆分；
- 训练、推理、组装、对角化和后处理成本；
- NaN/Inf、哈希错误、泄漏、basis/overlap 错配、键错位和残差超限失败样例。

全部数值容差必须在完成 M9-04 数据清单、官方配置和精度核对之后，且在任何 M9-05 训练、使用模型输出的验证、试推理或诊断之前登记。机读阈值清单必须包含指标定义、归一化、聚合、单位、适用子集、绝对/相对容差、依据来源、生成 UTC 和 SHA-256。冻结后只能因书写或实现错误通过新增决策保留旧值、修订理由和新值；不得依据已经观察到的模型结果放宽。物理重建与诊断累计预留不超过 6 GPU 小时。

### M9-07：复现报告与自动测试

项目侧形成环境、数据、训练、矩阵和物理验证的机读清单、自动测试、失败矩阵、复现命令和报告。任何结论都必须限定到冻结对象，不外推到 OpenMX 标签生成、其他材料、DeepH-E3、SOC 或磁性。

### M9-08：正式独立总审计

由新的独立子 agent 对实际安装对象、数据、代码、日志、自动测试、矩阵/物理结果、预算和授权边界执行审计。主 agent 修复问题后交回同一审计员定点复核，循环至新增及剩余问题均为 0，才允许 M9 `COMPLETED`。

## 5. 统一失败与停止规则

出现以下任一情况即停止当前门控并保留证据：

- 需要 Windows 重启；
- 7 天墙钟、24 GPU 小时、2/16/6 GPU 小时任一子桶或 100 GiB 存储达到上限，或预测下一原子操作会超过上限；
- 固定依赖或 GPU 兼容性失败；
- 下载对象 URL、大小或校验不符；
- 解压存在路径逃逸或异常链接；
- 数据契约不能支持冻结的验收对象；
- 训练出现 NaN/Inf、不可恢复 OOM 或达到子预算；
- 结构划分泄漏；
- basis、轨道顺序、相位、单位或 overlap 来源不一致；
- 为通过测试而需要在看到结果后放宽容差；
- 需要安装 OpenMX/其他 DFT 或生成标签；
- 需要更换 DeepH 版本、材料、后端、预算或高级物理范围。

所有停止项先报告，不以相邻版本、替代数据或缩小验收范围静默绕过。
